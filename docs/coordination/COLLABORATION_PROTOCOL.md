# 多角色协作与交接协议

## 标准循环

```text
读取公共账本和任务资料
→ 确认范围与验收标准
→ 实施或审查
→ 保存验证结果
→ 更新用户优化要求状态
→ 追加交接记录
```

## 公共记忆

`PROJECT_LEDGER.md` 是所有工作者共享的项目记忆入口。聊天记录和本地笔记不能替代 GitHub 中的正式记录。

## 并行协作

- 同一核心模块尽量只由一个任务分支修改。
- 发现范围重叠时，在账本登记 `BLOCKED` 并协调顺序。
- 评审期间只处理明确反馈，不顺带扩大任务范围。
- 用户新增优化要求先登记 OPT 编号，再决定进入当前任务或后续计划。

## 合格交接

交接记录应回答：做了什么、为什么、改了哪些文件、如何验证、什么尚未完成、有什么风险、下一位从哪里继续。
