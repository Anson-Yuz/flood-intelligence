# ADR-0001：云边协同积水智能契约与安全边界

- **级别：** C3（跨边端、云端、持久化数据与安全关键边界）
- **状态：** Proposed
- **日期：** 2026-07-10
- **关联：** Issue #1
- **决策范围：** Challenge Cup 评审级演示、Ubuntu 边缘采集、云端接入、可解释推理、审计与联动安全

本分支实现为评审候选，合并与生产采用需通过 Issue #1/PR 的人工及多方审查。

## 背景

预鉴需要在 Challenge Cup 评审环境中稳定展示“道路基线感知—当前积水识别—15/30/60 分钟趋势预判—人工处置—审计回放”的产品闭环，同时保留后续接入真实镭神激光雷达与摄像机、扩大试点和切换生产数据库的工程路径。

当前系统存在四类必须统一处理的约束：

1. 评审现场需要可重复、可离线准备的确定性演示，不能依赖降雨恰好发生或真实设备始终在线。
2. 边端运行于 Ubuntu，实际镭神型号和官方 SDK 尚需按最终采购设备锁定，平台不能虚构或耦合某个私有协议。
3. 道路积水预测涉及公共安全。雨滴反光、水深反演和趋势算法仍需实测验证，演示输出不能被误当作已验收的自动控制依据。
4. 政府客户要求结果可追溯。原始观测、DEM、质量、推理步骤、规则版本、人工决策和终端回执必须能够通过统一身份、事件时间和 trace 关联。

## 决策

采用一个版本化、可重放的云边事件契约，并以显式归一化层连接边缘协议与云端领域模型。Challenge Cup 演示、真实设备接入和后续生产部署共享同一领域语义，但必须标注不同证据等级，且默认不连接真实执行器。

### 1. Challenge Cup 评审级演示

- 前端允许使用确定性模拟夹具，FastAPI 使用幂等种子数据和固定场景序列，保证刷新或新建场景后可重复展示。
- 所有模拟点位、设备状态、预测精度、养护金额和联动结果必须显示“模拟态势 · 待接入实测”“设计目标”或对应证据等级。
- 演示后端是真实可运行的软件实现，但“软件链路可运行”不等于“感知算法精度已通过现场验收”。
- 演示可展示动作建议、人工确认、命令回执和审计链；默认不得向真实道闸、泵站、LED 或广播终端下发动作。

### 2. Ubuntu 镭神 LiDAR 与摄像机适配

- Ubuntu 边缘进程通过 `LidarVendorAdapter` 和 `CameraVendorAdapter` 隔离厂商 SDK、V4L2/GStreamer、标定及算法实现。
- 当前 mock adapter 只模拟中立观测，不模拟任何具体镭神型号、端口、点字段、扫描线数或私有数据包。
- 真实适配器必须依据最终型号的官方 Ubuntu SDK 实现，并把厂商对象转换为中立 DEM 元数据或水状态/边界观测；厂商私有类型不得进入平台事件信封。
- 大体积点云、DEM 栅格和证据帧使用对象或文件存储，事件只携带版本、引用、内容哈希、标定信息和质量状态。

### 3. HTTP/MQTT 统一事件信封

HTTP POST 请求体与 MQTT 消息体使用同一个 `yujian.edge.event/v1` JSON 信封。必需语义包括：

| 字段 | 契约 |
|---|---|
| `eventId` | 全局唯一幂等键；重试时不得重新生成 |
| `eventType` | 带版本事件名，如 `water.state.v1` |
| `occurredAt` | 带时区的实际观测时间 |
| `producedAt` | 带时区的信封生成时间 |
| `sequence` | 边缘节点持久化递增序号，用于发现缺口，不替代事件时间 |
| `traceId` | 串联同次水状态、边界、推理、告警、人工决策和回执 |
| `source` | `tenantId` 与 `edgeNodeId` |
| `subject` | `siteId`、`stationId` 与可选 `pointId` |
| `quality` | 状态、0–1 置信度和原因列表 |
| `context` | 配置、适配器、DEM、模型和标定版本 |
| `payload` | 事件专属业务数据 |

MQTT 主题采用：

```text
yujian/v1/{tenantId}/{siteId}/{stationId}/events/{eventType}
```

MQTT 使用 QoS 1 且不 retain。HTTP 任意 2xx 表示服务端已接受当前 `eventId`。

### 4. SQLite WAL outbox、幂等与补传

- 边端采用“先写 SQLite、再尝试网络发送”的 transactional outbox 顺序。
- SQLite 启用 WAL 和 `synchronous=FULL`；发送失败保留原始信封并指数退避，进程重启或网络恢复后继续补传。
- 投递语义为 at-least-once。服务端必须按 `eventId` 去重，并对重复事件返回已接受/重复，而不是再次产生水状态、预测或动作。
- 服务端成功接收但边端尚未删除 outbox 项时发生崩溃，允许重复发送；不允许通过生成新 `eventId` 隐藏该重复。
- 磁盘满、数据库损坏或 outbox 持续积压属于显式健康故障，不能静默丢弃最旧事件。

### 5. FastAPI 归一化与旧版兼容

- FastAPI `/api/v1/edge/v1/telemetry` 原生接收 `EdgeUnifiedEnvelope`，同时保留早期扁平 `EdgeTelemetryEnvelope`。
- 显式适配/归一化层把 `water.state.v1` 转换为内部水状态领域对象，并分别处理 `edge.heartbeat.v1`、`water.boundary.v1`、`road.dem.metadata.v1` 和 `edge.command.ack.v1`。
- 归一化必须保留 `eventId`、`traceId`、观测时间、sequence、质量原因、DEM/标定/适配器版本，不得只改事件名后丢失审计语义。
- 旧版扁平兼容入口暂不移除；新增协议版本仍通过该适配层路由，并由 edge 示例 payload 和服务端契约测试共同约束。
- 身份结构兼容不代表任意身份可入库。`tenantId`、`siteId`、`stationId` 和边缘节点必须对应服务端注册关系，否则拒绝接收。

### 6. 数据库选择

- Challenge Cup 本地演示默认使用 SQLite，降低启动依赖并支持离线评审。
- Docker Compose 和后续部署通过 `DATABASE_URL` 切换 PostgreSQL；业务代码通过 SQLAlchemy 保持相同领域模型。
- SQLite 只承担单机演示和开发，不被视为多实例、高并发或高可用生产数据库。
- PostgreSQL 是云端生产候选；切换数据库不得改变事件幂等、推理 trace 或审计哈希语义。

### 7. L1–L4 可解释推理契约

每次预测必须形成可回放的 L1–L4 链：

| 层级 | 最小输出契约 |
|---|---|
| L1 数据质量 | 输入引用、缺失/异常标记、质量分、补位或拒绝原因 |
| L2 当前状态 | 平均/最大水深、面积、体积、分段水深、1/5/10 分钟斜率、排水饱和状态 |
| L3 趋势预判 | 15/30/60 分钟深度及区间、达险时间、规则版本、案例修正依据、物理校验结果 |
| L4 决策输出 | 风险等级、行动建议、是否需人工确认、通知和后续回执状态 |

贯穿全链路的最小版本引用包括：

- `demVersion`、DEM 捕获时间、栅格/高程基准和内容哈希；
- `calibrationVersion`、相机/雷达适配器与算法版本；
- 当前水深、面积、体积和上涨/回落趋势；
- 置信度总分及其数据质量、趋势稳定性、气象质量和案例匹配构成；
- 规则版本、输入快照、物理约束通过/拒绝记录；
- 人工确认者、理由、时间和终端回执。

LLM 可以把结构化结果转换为文本，但不得生成或覆盖核心水深、达险时间、置信度和动作状态。

### 8. 模拟数据与实测证据等级

采用项目内部证据等级，并在 UI、API、导出报告和答辩材料中保留标签：

| 等级 | 含义 | 可支持的表述 |
|---|---|---|
| E0 模拟 | 固定夹具、mock 设备、仿真或人工构造数据 | 证明界面、协议、推理和审计流程可运行 |
| E1 受控实验 | 标定池或受控降雨、独立水尺/水位计真值 | 支持限定条件下的算法误差报告 |
| E2 现场试点 | 多场独立自然降雨、事件级留出测试 | 支持试点场景中的性能结论 |
| E3 独立验收 | 第三方、多点位、多季节及批准的验收方案 | 支持采购验收或生产服务等级声明 |

该分级是项目治理约定，不是国家或行业认证标准。E0 数据不得用于宣称雨滴反光、水深或趋势精度已实测达标；连续视频帧不得冒充大量独立降雨事件。

### 9. 自动联动安全边界

- 所有可能改变物理世界的动作默认进入“待人工确认”，包括关闸、开泵、广播和交通诱导。
- 默认配置不连接真实下控通道；edge 命令白名单仅允许采集、心跳和补传。
- 演示中的“自动联动”只表示自动生成候选建议或虚拟终端状态，不表示无人值守控制。
- 生产下控必须另行通过安全评估，并具备签名、短 TTL、幂等键、目标白名单、现场车辆/设备互锁、本地急停和实际状态回读。
- 数据降级、DEM 失效、时钟异常、命令过期、网络断开或设备离线时禁止生成新的物理控制动作。
- 风险解除不得自动触发解封；需满足稳定窗口和人工确认。

### 10. 重放、边界测试与回退

必须保留以下验证和运行行为：

**重放：**

- 相同 `eventId` 重放不产生重复水状态、预测、告警或动作。
- 相同观测的水状态与边界共享 `traceId`，并可按事件时间重建推理顺序。
- 规则、DEM、标定或模型版本必须冻结或可定位，确保历史结果可以解释。

**边界测试：**

- 统一信封与旧版扁平信封均有契约测试。
- 覆盖时区缺失、置信度越界、未知 schema、未知事件类型、未注册站点、序列缺口、乱序/迟到、重复事件和无效多边形。
- 覆盖 HTTP 超时/5xx、MQTT broker 重启、边缘进程重启、SQLite outbox 补传和服务端幂等。
- 预测测试按独立事件划分，不允许相邻帧同时进入训练与测试。

**回退：**

- 网络不可用：保留 outbox，继续本地健康监测，恢复后补传。
- 统一信封某一新版本不可识别：拒绝并保留原事件，不做有损猜测；旧版兼容端点仅服务已知旧结构。
- 摄像头质量或算法置信度不足：降级为记录/人工关注，不生成物理控制动作。
- DEM 过期或标定漂移：冻结水深推演、标记基线失效并要求复扫/重标定。
- 案例库不足或物理约束失败：回退到已知有效的确定性规则结果，扩大不确定区间并记录原因。
- 云端不可用：边端不自行升级为自动控制器。

## 替代方案

### A. 每种设备建立独立 HTTP 接口

**未采用。** 设备接入直观，但会把具体型号和字段扩散到云端，难以统一重放、MQTT、审计和后续型号替换。

### B. 仅使用 MQTT，不提供 HTTP

**未采用。** MQTT 适合长期设备连接，但增加评审环境和本地联调依赖；HTTP 更容易进行契约测试和故障定位。两者共享信封可避免业务协议分叉。

### C. 边端直接写云数据库

**未采用。** 这会暴露数据库凭据、绕过服务端校验与审计，并使断网、迁移和多租户隔离更困难。

### D. 不设置本地 outbox，发送失败即丢弃或仅内存重试

**未采用。** 城市暴雨时通信最可能不稳定；内存队列无法抵抗进程重启，且不能证明数据缺口。

### E. 只接受统一信封，立即移除旧版扁平结构

**暂未采用。** 这能简化服务端模型，但会破坏已有演示、测试和潜在早期调用方。保留显式兼容层的成本可控，后续在有迁移统计和弃用计划后再评估移除。

### F. 纯黑盒模型或 LLM 直接给出预测和动作

**未采用。** 无法满足政府客户对公式、输入、物理约束和责任链的复核要求，也难以稳定重放历史决策。

### G. 高置信度时直接自动关闸

**未采用。** 感知算法尚未达到 E3 证据等级，且关闸本身可能造成追尾、拥堵或阻断救援。默认人工确认和无真实下控是本 ADR 的安全不变量。

## 后果

### 正面后果

- Challenge Cup 演示可离线、可重复，同时明确与实测生产结论的边界。
- 厂商 SDK 与平台契约解耦，后续可按实际镭神型号替换适配器。
- HTTP/MQTT、断网补传和服务端幂等共享一个事件语义。
- SQLite 演示与 PostgreSQL 部署共用领域模型，降低环境切换成本。
- L1–L4 和版本引用形成可审计、可复核的证据链。
- 人工确认与默认无真实下控降低算法不确定性造成的公共安全风险。

### 负面后果与成本

- 统一信封与旧版扁平结构并存，服务端需要维护归一化代码和双契约测试。
- at-least-once 语义要求所有有副作用的服务端处理按 `eventId` 幂等。
- SQLite outbox 需要磁盘容量、损坏检测和积压监控，不能视为零运维组件。
- 完整审计会增加存储、版本管理和隐私治理成本。
- 人工确认会增加处置延迟；在没有独立安全论证前，这是接受的安全权衡。
- 证据等级会限制市场宣传口径，但可避免把模拟结果误表述为实测能力。

## 验证与演进条件

本决策通过以下条件持续验证：

- edge 单元测试与离线补传自测持续通过；
- FastAPI 统一信封、旧版信封、幂等和辅助事件专项测试持续通过；
- PowerShell 一键脚本语法与 Docker Compose 配置持续校验；
- 任何新事件版本必须补充 golden payload、归一化测试和回放测试；
- 任何真实下控需求必须提交新的 C3 ADR 或安全评估，不得通过配置开关绕过本决策；
- 当旧版扁平信封已有可观测的零调用期和批准的迁移计划时，可另立 ADR 讨论移除；
- 当算法取得 E2/E3 证据时，可更新性能声明，但不得追溯性改变历史记录的证据等级。
