# 挑战杯五分钟演示脚本

目标：在 5 分钟内稳定说明“提前预判、人工安全处置、全过程可追溯、全年路面价值”。所有数值均按“模拟态势 · 待接入实测”或“设计目标”标注，不把界面结果称为现场实测结论。

## 演示前复位（2 分钟准备，不计入路演）

```powershell
cd D:\yujian-platform
.\stop-demo.ps1
.\start-demo.ps1
```

确认：

1. 前端 `http://127.0.0.1:5173` 可打开。
2. `http://127.0.0.1:8000/api/v1/health` 返回 `status=ok`、`seeded=true`。
3. 浏览器缩放 100%，刷新页面。前端交互使用确定性夹具，刷新即可回到初始状态。
4. 关闭无关窗口和通知，不在演示中现场安装依赖。

如果要演示后端确定性场景，可在演示前创建一个暂停运行：

```powershell
$body = @{ siteId = "site-binh-rd-tunnel"; speed = 1; autoRun = $false } | ConvertTo-Json
$run = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/api/v1/scenarios/rapid-inundation/start" -ContentType "application/json" -Body $body
$run.id
```

每次重新调用都会得到内容相同、ID 不同的新运行，不需要清空数据库。

## 0:00–0:30 开场与边界

操作：打开“城市积水风险总览”。

讲解：

> 预鉴解决的不是“水已经多深”，而是“未来 15 到 60 分钟会到什么程度、现在应该做什么”。今天展示的是确定性模拟态势，雨滴反光算法和精度指标仍需现场验证，所有道闸动作都是建议和模拟，不控制真实设备。

必须让评委先看到页面上的“模拟态势 · 待接入实测”标签，并说明辖区照片为实景参考，不是实时监控。

## 0:30–1:15 风险总览：从当前到未来

操作：

1. 切换 15/30/60 分钟预测窗口。
2. 选中“滨河路下穿隧道北口”。
3. 指向当前水深、预测水深、达险时间、置信度和排水饱和状态。

讲解：

> 系统把点位当前状态和未来趋势放在同一屏。滨河路当前并非只报一个水位，而是给出预测曲线、预计达险时间和置信度，让值班人员获得前置处置窗口。

不要说“预测一定准确”，应说“结构化展示设计目标及不确定性”。

## 1:15–2:05 事件中心：算法建议与人工边界

操作：进入“事件指挥中心”，选择第一条红色事件，展示建议动作、责任人和时间线；点击“确认并接管”或指向该按钮。

讲解：

> 高置信结果会形成处置建议，但算法风险态不等于道闸控制态。竞赛原型中由人员确认并接管；生产环境还要经过命令签名、现场车辆检测和独立安全控制器。数据质量不足时只提示关注，不自动执行。

若已点击导致界面状态变化，刷新页面即可复位。

## 2:05–2:55 推理审计：回答“为什么”

操作：进入“推理审计与履职证据链”，依次点选 L1、L2、L3、L4 记录；点击“验证完整性”。有余量再展示“导出存证包”。

讲解：

> 每次结果保留输入、DEM/标定/规则版本、中间计算、物理约束、人工操作和终端回执。这样政府客户看到的不只是一个 AI 数字，而是一条可复核的决策链。当前是防篡改审计演示，不直接宣称司法证据效力。

## 2:55–3:35 云边协同：断网也不丢

操作：进入“边端站点管理”，选中 LiDAR 或摄像头设备，指出工作模式、心跳、DEM/标定版本和自检入口。

讲解：

> Ubuntu 边缘站把镭神 SDK 隔离在厂商适配器后。平时 LiDAR 间歇扫描更新 DEM，降雨时摄像头输出候选边界。事件先写 SQLite，再经 HTTP/MQTT 上报；断网时本地排队，恢复后按同一 eventId 补传，云端幂等去重。

如被追问具体镭神型号：回答“当前未锁定采购型号，因此没有虚构协议；按最终型号官方 Ubuntu SDK 接入”。

## 3:35–4:20 可交互模拟：说明阈值与不确定性

操作：进入“积水预报交互模拟器”，选择“下穿隧道强降雨”，点击“运行模拟”；再降低置信度或选择“老旧道路缓慢积水”。

讲解：

> 同样的水深在不同上涨速率、排水能力和置信度下会得到不同建议。高置信候选进入人工确认，60%到85%只推送关注，低于60%仅内部记录。模拟器展示决策逻辑，不是实测算法精度证明。

## 4:20–4:50 全年价值：从防汛到养护

操作：进入“道路养护优先级决策”，切换预算档位，展示沉降、劣化速率、交通量和积水风险排序。

讲解：

> 同一套设备非汛期还能比较 DEM 变化，为有限养护预算提供排序依据。这让预鉴不只在暴雨当天有价值，也服务日常道路养护。这里的金额和 IRI 是演示估算，需经现场标定和主管部门规则确认。

## 4:50–5:00 收束

讲解：

> 预鉴把“看见积水”推进为“提前预判、人工安全处置、全程可追溯”，同时用全年路面数据提高设备利用率。下一步不是扩大宣传口径，而是用独立水位真值完成多雨强、多光照、多路面的事件级验证。

## 可重复后端操作（答辩备用）

精确推进刚创建的场景一分钟：

```powershell
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/api/v1/scenarios/runs/$($run.id)/step"
```

验证后端审计链：

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/audit/verify" | ConvertTo-Json -Depth 6
```

查看聚合状态：

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/dashboard" | ConvertTo-Json -Depth 5
```

## 故障兜底

- 前端仍可单独展示确定性夹具；明确说明后端服务暂不可用，不伪造实时联机。
- 若某个交互状态不对，刷新浏览器即可复位。
- 若 5173/8000 被占用，演示前用 `start-demo.ps1 -FrontendPort 5174 -BackendPort 8001`，不要在台上排查端口。
- Docker 首次拉取和依赖安装不适合现场进行；演示前完成并确认 `docker compose ps` 全部 healthy。
- 不现场演示真实关闸，不展示或输入任何真实设备凭据。
